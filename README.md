# Companies House Lead Intelligence Engine

Automated pipeline that ingests newly incorporated UK companies from the Companies House API, enriches each record with named director data, scores leads by sector and recency, and delivers a ranked outreach-ready spreadsheet for accountancy practices.

---

## The Problem

Small UK accountancy practices have no systematic way to identify newly incorporated businesses before competitors do. The Companies House register updates in near real time, but the raw data is unfiltered: thousands of incorporations per month, mixed with dormant vehicles, holdcos, nominee structures, and dissolved entities. A practice relying on referrals or manual checking will always be weeks behind.

This engine automates the full pipeline — ingest, filter, enrich, score, deliver — so a practice can reach a new director within days of incorporation, when the relationship is easiest to win.

---

## What It Produces

A weekly leads export with one row per live, scoreable company, containing:

- **Lead Score (0–100)** — computed from recency, geography, company type, and SIC sector
- **Priority band** — `high` / `medium` / `low`; excluded entities are suppressed entirely
- **Director name** — resolved to natural order (forename surname) from the officers endpoint
- **Director appointed date** — exact date recorded on Companies House
- **Suggested outreach line** — a sector- and geography-aware sentence, ready to paste into an email

Outputs: `outputs/leads_export.csv`, `outputs/summary.csv`, `outputs/demo-leads-london-jun2026.xlsx` (colour-scaled by score).

## How It Works

```
fetch_events.py  →  company.py  →  lead_scorer.py  →  csv_export.py
   (ingest)          (enrich)        (score)             (deliver)
```

Orchestrated by `scripts/run_pipeline.py`, which runs the four stages in sequence, passing data through `fixtures/` as intermediate JSON.

### 1. Ingest — `app/ingest/fetch_events.py`

Queries the Companies House advanced search endpoint for companies incorporated in the last 30 days (`incorporated_from` / `incorporated_to`). For each result, a second request hits `/company/{number}/officers` to retrieve the first active director — filtered for `officer_role == "director"` and no `resigned_on` field. Raw results are cached to `fixtures/raw_events.json`.

### 2. Enrich — `app/enrich/company.py`

Parses raw API responses into typed `EnrichedCompany` Pydantic models. Computes `company_age_days` from today's date. Extracts a `region` field from the registered office address, preferring the `locality` field and falling back to the first two characters of the postcode (e.g. `SW` implies London).

### 3. Score — `app/score/lead_scorer.py`

Scores each company 0–100 using an additive point system, applied only after hard-exclusion filters pass.

**Exclusion filters** (score = 0, suppressed from output):
- Company status is `dormant`, `dissolved`, `liquidation`, or `administration`
- SIC code is `99999` (non-trading) or `98000`
- Company name contains `holdings`, `nominee`, `trustee`, or `dormant`

**Scoring signals:**

| Signal | Points |
|---|---|
| Incorporated < 30 days ago | +40 |
| Incorporated 30–90 days ago | +25 |
| London-based (by locality or postcode prefix) | +20 |
| Private limited company (`ltd` / `private-limited-company`) | +20 |
| Tech / IT sector (SIC 62000–63199) | +15 |
| Property / real estate (SIC 68000–68399) | +10 |
| Three or more SIC codes | +5 |

Score is capped at 100. Bands: `high` > 70, `medium` ≤ 70, `low` ≤ 40.

### 4. Deliver — `app/deliver/csv_export.py`

Joins scored leads with enriched company data and writes three outputs:

- **`leads_export.csv`** — full column set, UTF-8-sig encoded for Excel compatibility
- **`summary.csv`** — four-column digest (Company Name, Region, Priority, Suggested Outreach)
- **`demo-leads-london-jun2026.xlsx`** — formatted workbook with bold dark-header row, auto-sized columns, and a red-to-green conditional colour scale on the Lead Score column

Outreach lines are generated by detecting sector and geography signals from the score reasons, then selecting from four pre-written variants per segment. `hash(company_name) % len(variants)` ensures a given company always maps to the same variant — deterministic rotation with no database or state required.

## Key Engineering Decisions

**Rate limiting on the officers endpoint.** The Companies House API enforces 600 requests per 5 minutes. The ingest module applies a 0.5-second inter-request delay in the `finally` block of `fetch_first_active_director` — so it runs even on exception — keeping the pipeline well inside the limit across batches of 50 companies.

**`try/except` fallbacks on officer lookup.** Network timeouts and 404 responses on the officers endpoint are caught, logged as warnings, and return `("Not listed", None)`. The pipeline never aborts because one company has no director on record; missing data propagates gracefully to the export.

**UTF-8-sig encoding.** Both CSV outputs use `encoding="utf-8-sig"`. The byte-order mark causes Excel on Windows to detect UTF-8 rather than defaulting to a Windows code page, which prevents character mangling on companies with non-ASCII names.

**Dormancy and holdco exclusion.** Rather than relying on SIC codes alone, the exclusion logic checks three independent signals: company status, non-trading SIC codes, and name-word heuristics (`holdings`, `nominee`, `trustee`, `dormant`). This catches structural entities that pass the incorporation date filter but would be dead ends for outreach.

**Hash-based outreach line rotation.** Each scoring segment (tech+London, property, generic London, etc.) has four pre-written outreach variants. Selecting by `hash(company_name) % 4` means the same company always receives the same line across pipeline runs — no state, no database, consistent output.
